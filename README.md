# Arth-Sutradhar (The Economic Narrator)

A multi-agent, multimodal RAG system for the **RAG Over Bharat** hackathon. Bridges micro-level rural land records with macro-level government statistics using Google Cloud's AI ecosystem.

**Live API:** `https://arth-sutradhar-api-638364788058.asia-south1.run.app`

---

## Architecture

```
User Input (Text / Voice / Image)
    │
    ▼
┌─────────────────────────────────────────────────────┐
│           ADK Agent Orchestrator                     │
│                                                      │
│  Phase 1: Planner (keyword-based task decomposition) │
│  Phase 2: Search Fanout (BQ + MCP in parallel)      │
│  Phase 3: Context Check (sufficiency gate)           │
│  Phase 4: Query Rewriter (self-correction loop)      │
│  Phase 5: Gemini 2.5 Flash Synthesis (narrative)     │
└────┬──────────────────────────┬──────────────────────┘
     │                          │
     ▼                          ▼
┌────────────────┐    ┌──────────────────────────┐
│ BigQuery       │    │ e-Sankhyiki MCP           │
│ VECTOR_SEARCH  │    │ (live MoSPI economic      │
│ on land        │    │  datasets via 4-step       │
│ record chunks  │    │  protocol)                │
└────────────────┘    └──────────────────────────┘
     │                          │
     ▼                          ▼
┌─────────────────────────────────────────────────────┐
│  Translation Layer (off-project, optional)           │
│  Google Translate v2 REST API via httpx + ADC        │

└─────────────────────────────────────────────────────┘
```

## Tech Stack & How Each Tool Is Used

### Google Cloud Platform

| Service | What We Use It For |
|---------|-------------------|
| **Vertex AI (Gemini 2.5 Flash)** | Phase 5 synthesis — receives all retrieved context (land records + macro data + reasoning log) and generates a grounded narrative response. Called via `google-genai` SDK with `vertexai=True` on `us-central1`. Model: `gemini-2.5-flash`. System prompt enforces factual grounding. |
| **BigQuery VECTOR_SEARCH** | Stores ~5000 land record chunks with embeddings generated by `ML.GENERATE_TEXT_EMBEDDING` (BQML). Phase 2 runs cosine-similarity search against user query. Schema: `chunk_id`, `content`, `source_file`, `content_embedding`. |
| **Cloud Run** | Hosts the FastAPI backend. Stateless, auto-scaling, 2Gi RAM, 2 CPU, 300s timeout. Service account has `aiplatform.user` + `bigquery.dataViewer` + `bigquery.user` roles. |
| **Cloud Build** | CI/CD pipeline. Builds Docker image from `frontend/api/Dockerfile` and pushes to Artifact Registry on each deploy. |
| **Artifact Registry** | Stores Docker images tagged by region/service. |
| **Cloud Storage** | Cloud Build source staging. Also stores Terraform state. |
| **Translate API** | (Optional) On-the-fly translation of user queries. If `language` is `"hi"`/`"gu"`, translates to English before agent run, then translates response back. Uses `google.auth` ADC for auth, no API keys needed. |
| **Vertex AI Agent Development Kit (ADK)** | The orchestrator pattern (5-phase loop) is inspired by the Sufficient Context Agent pattern from Google's ADK. Implemented in native Python, not using the ADK Python library. |

### AI Models

| Model | Location | Usage |
|-------|----------|-------|
| `gemini-2.5-flash` | `us-central1` (via Vertex AI) | Phase 5 narrative synthesis. Config: `temperature=0.2`, `max_output_tokens=4096`, system instruction with grounding rules. |
| `text-embedding-005` or equivalent (BQML) | `asia-south1` | Generates embeddings for land record chunks during ingestion. Called via `ML.GENERATE_TEXT_EMBEDDING`. |
| `google-cloud-vision` | `asia-south1` | OCR on uploaded images (`/query/upload`). Extracts text from photos of land record documents. |

### Agent Architecture (5-Phase Loop)

```
Phase 1: Plan
  └─ Keyword matching on query → decide: land_records, macro_data, or both
Phase 2: Search
  ├─ BigQuery VECTOR_SEARCH(query) → top-10 land records
  └─ MCP(list_datasets → get_indicators → get_data) → macro data points
Phase 3: Context Check
  └─ If any source returned empty → mark as incomplete → allow iteration
Phase 4: Rewrite (only if Phase 3 incomplete)
  └─ Append location/year hints → re-run Phase 2 (max 3 iterations)
Phase 5: Synthesize
  └─ Gemini 2.5 Flash(all_context + reasoning_log) → narrative report
  └─ Fallback: string concatenation if Gemini API unavailable
```

### e-Sankhyiki MCP Integration

Connects to MoSPI's MCP server via a 4-step protocol:

1. `list_datasets()` — discovers available datasets (PLFS, CPIALRL, ASUSE)
2. `get_indicators(dataset_id)` — fetches indicator list per dataset
3. `get_metadata(dataset_id, indicator_id)` — fetches metadata
4. `get_data(dataset_id, indicator_id, state_code, financial_year)` — fetches actual data values

Each step has a cached fallback if the MCP server is unreachable, returning realistic mock data.

### Translation Layer

When a query comes in with `language: "hi"` or `"gu"`:

1. Detect language (if `"auto"`) or use provided language code
2. Translate query to English via `translation.googleapis.com/v2`
3. Run the agent (English-only)
4. Translate response back to the original language
5. Return with `source_language` field set

Uses `google.auth` default credentials (works on Cloud Run without any config). Falls back gracefully if translation fails.

## API Endpoints

### `POST /query`

Submit a text question with optional language code.

```json
{
  "text": "ગુજરાતમાં કપાસના ખેડૂતો માટે જમીનના રેકોર્ડ બતાવો",
  "language": "gu"
}
```

Response:

```json
{
  "response": "Gemini-synthesized narrative analysis...",
  "iteration_count": 1,
  "feedback_log": ["Plan created: [...]", "BigQuery returned 10 records", "..."],
  "source_language": "gu"
}
```

### `POST /query/upload`

Upload an image of a land record document. OCR extracts text, auto-detects language, translates to English, runs agent.

### `GET /health`

Health check. Returns `{"status": "ok", "project": "arth-sutradhar"}`.

## Key Design Decisions

- **Gemini in us-central1, API in asia-south1**: Gemini 2.5 Flash is not available in `asia-south1` yet, so the agent calls it cross-region. The FastAPI server and BigQuery stay in `asia-south1`.
- **google-genai SDK over vertexai SDK**: The `google-genai` package (v2.x) is the newer unified SDK. With `vertexai=True`, it routes through Vertex AI endpoints. More reliable for model discovery.
- **Self-correction loop**: If both data sources return empty, the agent appends hints ("Gujarat land records", "India stats latest year") and retries up to 3 times.
- **Fallback synthesis**: If Gemini is unreachable (quota, permissions, network), falls back to plain-text concatenation of raw data.
